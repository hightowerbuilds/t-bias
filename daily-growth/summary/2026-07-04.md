## Session — Phase 1: PTY + alacritty_terminal spine (make-or-break) ✅

One live terminal end to end, in `app/src/terminal.rs` (commit `f572fdf`). Zed's 3-layer
architecture:
- `TbiasListener` — alacritty `EventListener` forwarding events to the UI over a `futures`
  unbounded channel (added `futures = "0.3"`).
- `Term<TbiasListener>` behind `Arc<FairMutex<_>>`; our own `TerminalSize: grid::Dimensions`
  (alacritty's `TermSize` lives in a `test` module).
- `portable-pty` login shell (`-l`, `TERM`/`COLORTERM`, cwd `$HOME`; env inherited so PATH works).
- `pty_reader_loop` thread: PTY → `vte::ansi::Processor::<StdSyncHandler>::advance(term)` → emit
  `Wakeup`; `Exit` on EOF. `pty_message_loop` thread: Input/Resize/Shutdown → PTY; `Drop` kills
  the child.
- `main.rs` `Root` view spawns a gpui task draining the channel (burst-coalesced into one
  `cx.notify()`), handles shell exit.

Verified headlessly (screen capture is blocked in this env): drove startup commands and read
back the parsed grid — real zsh prompt, `echo` output, `uname -a` + `ls` all present. Full
PTY → VTE → Term → UI path confirmed.

## Session — Phase 2: terminal cell rendering ✅

Real cell renderer in `app/src/terminal_view.rs` (commit `8d83f44`), built on GPUI's `canvas`
element (low-level paint API, no custom `Element` boilerplate):
- Measures Menlo 14 via the text system (cell width from `'m'` advance, line height `size×1.3`).
- `prepaint` computes cols/rows from painted bounds and reflows both the emulator grid and the

Verified headlessly: paint path runs without panic across 16-color/bold/underline/inverse/

## The Xcode detour — and the real fix: BLADE (`e312666`) ⭐

The make-or-break blocker: **GPUI rendered solid quads but NO text** — even a plain
`div().child("...")` was invisible; only the cursor block showed. Chased it hard:
`runtime_shaders` → installed Xcode + the Metal Toolchain (688MB) to get precompiled Metal
shaders → **text was STILL invisible.** Root cause: GPUI's **Metal backend renders no glyphs on
this Intel + AMD dual-GPU Mac (macOS Tahoe 26)** — a hardware/backend bug, not our code (our own
minimal GPUI hello-world was also blank).

The fix came from the user's own working repo **`hightowerbuilds/llnzy`**: use the published
**`gpui = "=0.2.2"` from crates.io with `features = ["macos-blade"]`** — the **Blade** renderer
(wgpu/naga). Blade renders text correctly here, and compiles shaders via naga, so **Xcode was
never needed.** Switched the dep, fixed a few 0.2.2 API deltas (`Application::new()`,
`window.focus(&h)`, `ShapedLine::paint(origin, lh, window, cx)`). **Text rendered. First time
seeing the terminal for real** — prompt, colors, typing all work. Lesson saved to memory
([[gpui-blade-renderer]]): on an Intel Mac, use crates.io gpui + macos-blade, never git/Metal.
