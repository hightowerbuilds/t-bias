### 3. Fix the Build (three real issues, in order hit)
1. **Toolchain:** rustc 1.94.1 rejected `std::hint::cold_path` as an unstable library feature
   used inside this `gpui` rev. Zed's own tree pins stable **1.95.0**, which stabilizes it.
   Installed 1.95.0 via `rustup` and pinned it for the crate with `app/rust-toolchain.toml`.
2. **API shape:** `Application::new()` doesn't exist at this rev — the Zed tree moved platform
   construction into a separate `gpui_platform` crate. Added it as a dependency and switched
   `main.rs` to `gpui_platform::application().run(...)`.
3. **Xcode assumption, corrected:** `gpui_macos`'s default build shells out to `xcrun metal` to
   precompile a shader, which requires full Xcode.app (not just Command Line Tools) — this
   machine only has CLT. Initially concluded Xcode was a hard requirement and asked the user how
   to proceed; **the user correctly pushed back** ("we've done this before with GPUI and didn't
   need Xcode"). Re-investigated and found `gpui_macos`/`gpui_platform` expose a
   `runtime_shaders` feature that stitches the shader source and compiles it at *runtime* via
   the Metal framework API instead of the `metal` CLI — sidesteps Xcode entirely. Enabled via
   `gpui_platform = { ..., features = ["runtime_shaders"] }`.
