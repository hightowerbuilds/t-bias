### 2. Direction: PS2 Controller Terminal
New north star. Wrote `daily-growth/roadmaps/ps2-terminal-roadmap.md` — 9 phases, locked stack,
known snags recorded up front, and the same de-risk-first discipline that made the GPUI rebuild
work (spine → pad model → verbs → typing).

**Key architectural finding:** the existing code was already factored for this.
`input.rs::encode_key` is a pure `(key, key_char, mods, app_cursor) -> Option<Vec<u8>>`, so the
pad layer emits *the same bytes* and nothing downstream changes. And the
background-thread → channel → `cx.spawn` drain pattern already existed twice
(`pty_reader_loop`, the flip timer). The gamepad loop is a third instance of a proven pattern.

**Hardware scan:** a **DualShock 4** (`054C:05C4`) is paired to this Mac but currently asleep.
No USB gamepad adapter present. Decision: code against an abstract PlayStation layout, use the
DS4 for development, treat a real DS2-via-adapter as a mapping-table entry.

**Deferred by design:** the text-entry scheme (radial chord vs on-screen grid vs dual-stick)
is kept behind a `TextEntry` trait. Every scheme needs an identical Phase 0, so building the
spine first commits to nothing — and the choice is better made by feel on real hardware than
on paper.

### 3. Phase 0 — Controller spine (built)
`app/src/gamepad.rs`, plus wiring in `main.rs`:

- Dedicated `tbias-gamepad` thread owning `Gilrs`, polling at 125 Hz (<8ms button latency).
  **`Gilrs` is `!Send` on macOS** — it holds CoreFoundation types and pumps a CFRunLoop inside
  `next_event` — so it is created inside the thread and never moved. This was the main runtime
  risk and it is now cleared.
- Hot-plug handling; disconnect resets stick state so a stale deflection can't scroll forever.
  Controllers already awake at startup are announced explicitly (gilrs only emits `Connected`
  for devices arriving *after* init).
- Missing controller / missing gamepad subsystem are both non-errors — keyboard-only operation
  is unchanged.
- Toolbar indicator (`◉ <name>` / `○ no controller`), since the Phase 0 check is visual.

### 4. Phases 1-2 — Pad model and terminal verbs (mostly built)
- `PsButton` (abstract PlayStation layout) + gilrs mapping, including the bumper/trigger naming
  trap (`LeftTrigger` is L1, `LeftTrigger2` is L2 — getting it backwards is silent).
- 8-way sector quantization clockwise from north, with hysteresis on **both** the dead zone
  (enter 0.5 / exit 0.35) and the sector boundaries. This is the geometry the radial keyboard
  will sit on, so it's unit-tested rather than tuned by feel.
- Binding table routed **through `encode_key`** rather than emitting raw bytes: ○ = Ctrl-C,
  △ = Enter, □ = Tab, ✕ = Space, d-pad = arrows (application-cursor mode works for free),
  L1/R1 = history, L2/R2 = page scroll, right stick = analog scrollback.
- Start/Select left deliberately unbound — they belong to the Phase 5 modal system.
